# الزامات امنیت، حریم خصوصی و انطباق

## اصول P0
- **کمینه‌سازی داده:** فقط داده لازم برای خرید و تکالیف قانونی؛ بدون ذخیره اطلاعات کارت در سرور پلتفرم.
- **Least privilege و tenant isolation:** تمام درخواست‌ها در سطح رکورد و رابطه فروشنده بررسی شوند.
- **TLS و ذخیره‌سازی امن:** HTTPS، مدیریت secrets، رمزگذاری اسناد حساس در حالت سکون، چرخش credential.
- **احراز مدیر/فروشنده:** MFA برای نقش‌های حساس (نوع و روش تصویب شود)، نشست کوتاه‌تر، ثبت تغییر دستگاه/حساب بانکی، محدودکردن brute-force.
- **OTP:** انقضا، نرخ محدود، ثبت تلاش، جلوگیری از user enumeration، محافظت در برابر replay.
- **فایل‌ها:** بررسی نوع/اندازه و اسکن بدافزار، object storage خصوصی با URL زمان‌دار، حذف metadata غیرضروری.
- **ورودی و API:** validation، parameterized queries، محافظت در برابر تزریق، XSS، CSRF، SSRF، درخواست جعلی callback.
- **پرداخت:** تأیید امضای webhook در صورت پشتیبانی + استعلام مستقل از PSP، idempotency، عدم اعتماد به redirect کاربر.
- **Audit:** ثبت Actor، زمان، موجودیت، تغییر و علت؛ محافظت در برابر حذف/دستکاری سوابق؛ عدم درج PII در log.
- **بازیابی:** بکاپ رمزگذاری‌شده و تست دوره‌ای restore، runbook حوادث، مانیتورینگ عدم تطبیق موجودی/پرداخت.

## حریم خصوصی
- داده مشتری: تماس، نشانی، تاریخچه خرید، درخواست پشتیبانی.
- داده فروشنده: مدارک هویتی، مجوزها، اطلاعات قراردادی و مالی؛ جداسازی سخت از پروفایل عمومی.
- رضایت/اطلاع‌رسانی شفاف برای اهداف جمع‌آوری، اعلان بازاریابی و مدت نگهداری؛ مدت‌ها با قوانین و قرارداد تأیید شوند و به‌صورت حدسی تعیین نشوند.
- درخواست حذف/اصلاح داده با تفکیک تکلیف نگهداری اسناد مالی یا قانونی؛ صرفاً وعده «حذف کامل همه چیز» داده نشود.

## نگاشت کنترل به ریسک
| ریسک | کنترل اصلی | تست |
|---|---|---|
| مشاهده سفارش فروشنده دیگر | رکورد-لول authz | تست IDOR بین دو فروشنده |
| دستکاری مبلغ | quote immutable + server calculation | تغییر total در مرورگر |
| پرداخت دوباره | idempotency + PSP reconciliation | webhook تکراری |
| سوءاستفاده OTP | rate-limit و cooldown | تلاش انبوه |
| مدارک درزکرده | ACL، object storage خصوصی، redaction | آزمون URL عمومی |
| موجودی منفی | تراکنش/قفل | stress concurrent checkout |
| نرخ مخدوش | اعتبار منبع، threshold و fail closed | stale/rate anomaly |
| تغییر غیرمجاز تسویه | RBAC، تایید دوباره و audit | تغییر حساب توسط Support |

## کنترل کیفیت انتشار
- dependency و secret scanning، بررسی آسیب‌پذیری، مرور سطح حمله، تست نفوذ متناسب با مقیاس، تست بازگردانی بکاپ.
- برای تراکنش‌ها و هویت، پوشش تست و سناریوهای بحرانی باید قبل از Production ثبت شود.
- به‌کارگیری اصول OWASP ASVS و OWASP API Security به‌عنوان مرجع مهندسی؛ نسخه مناسب در زمان اجرا تعیین شود.
- نقش مسئول رخداد امنیتی، روش توقف پرداخت و بازیابی خدمت مشخص باشد.

## الزامات خارجی و گیت
صدور مجوز تخصصی بازارگاه، اینماد، مالیات، صورتحساب الکترونیکی، حمل/بیمه، مسئولیت فروشنده و راهکار PSP باید طبق مقررات **معتبر روز** بررسی شوند. این سند تأیید قانونی نیست؛ ارجاع: [مجوزها و ریسک‌ها](../تصمیم%20توسعه/مجوزها-و-ریسک‌ها.md).
