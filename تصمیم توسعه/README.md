# تصمیم‌های توسعه و معماری

**همه موارد زیر در وضعیت «پیشنهادی/باز» هستند مگر صراحتاً تصویب شوند.** هدف جلوگیری از تبدیل تحلیل اولیه به تصمیم قطعی تیم است.

| ID | موضوع | گزینه پیشنهادی فعلی | وضعیت | دلیل |
|---|---|---|---|---|
| ADR-001 | دامنه MVP | فروش مصنوعات فیزیکی چندفروشنده؛ نه طلای آب‌شده | باز | کاهش پیچیدگی مالی و قانونی |
| ADR-002 | موجودی | نزد فروشنده، با تأیید و رزرو پیش از پرداخت | باز | سرمایه اولیه کمتر |
| ADR-003 | سفارش | یک فروشنده در هر سفارش در MVP | باز | تسویه و حمل ساده‌تر |
| ADR-004 | رابط کاربری | وب واکنش‌گرا RTL / PWA در صورت نیاز | باز | اولویت استفاده موبایل |
| ADR-005 | فناوری | Next.js + Django/Laravel + PostgreSQL به‌عنوان گزینه‌های بررسی | باز | قابلیت رشد؛ نهایی نیست |
| ADR-006 | محاسبه قیمت | سمت سرور، با تاریخچه و نرخ اعتباردار | باز | جلوگیری از مغایرت و دستکاری |
| ADR-007 | تسویه | فقط با PSP/ارائه‌دهنده دارای مجوز مناسب | باز | رعایت الزامات مالی |
| ADR-008 | ورود فروشنده | احراز هویت، راستی‌آزمایی صنفی و قرارداد | باز | اعتماد و کنترل ریسک |

## قالب تصمیم جدید

- ID / عنوان / تاریخ / مالک / وضعیت (proposed, accepted, superseded)
- مسئله و محدودیت‌ها
- گزینه‌های جایگزین
- دلیل انتخاب
- هزینه‌ها، ریسک‌ها و معیار بازنگری
- لینک Issue یا PR اجراکننده

## گیت‌های پیش از شروع کدنویسی پرداخت
1. تعیین شخصیت حقوقی و مجوزهای لازم.
2. اعتبارسنجی مدل فروشنده/مالک کالا و شرایط مسئولیت طرفین.
3. مدل قیمت و فاکتور مورد قبول حسابدار و متخصص مقررات طلا.
4. انتخاب PSP/تسویه قانونی، مدیریت مرجوعی و حمل امن.
5. تعاریف دقیق MVP و معیارهای پذیرش.
